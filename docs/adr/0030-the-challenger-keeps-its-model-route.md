# 0030 — Keep `ChallengerAgent` on the `reason` tier, breaking a six-component run

## Chosen

`ChallengerAgent` makes a model call, on the `reason` tier ADR 0006 assigned it
in Phase 0. It stays out of `NON_LLM_AGENTS`, ending six consecutive components
that moved to the arithmetic side.

## Rejected

| Option | Why not |
| ------ | ------- |
| Make it deterministic, like the six before it | There is nothing to compute. The other six each turned out to be reading a record somebody had already written — an `estimated_as` edge, a `CONTRADICTS` edge, a `MatchQuality`, a distribution of ratios. A `Finding.prosecution` is prose, generated by whichever component filed it, and no table in this store holds the answer to "does this case hold up". Putting it in `NON_LLM_AGENTS` would mean writing a rule that pattern-matches prosecutions, which is a model with worse recall and no honesty about being one. |
| Score the finding arithmetically instead — confidence, severity, evidence count | That is a real component and it is `AbstentionGate` (ADR 0032). It answers a different question: whether the *evidence* is sufficient, not whether the *argument* is sound. Collapsing the two would lose the distinction the phase exists to draw, and would leave a finding with plenty of evidence and a fatal logical flaw sailing through. |
| Re-tier it to `extract` to save money | The output is an argument, and this is the one place in the pipeline whose job is to disagree with the rest of it. ADR 0006's `reason` rationale already names "the adversarial challenge" among the calls the product rests on. A cheaper challenger that concedes less is indistinguishable from a working one until a person has wasted a week on a finding nobody tested. |
| Skip the challenge for low-severity findings | Tempting, and wrong in the direction that matters. The findings most worth overturning are the ones whose severity outruns their evidence, and severity is assigned by the component that filed the finding — the same component whose work is being tested. Letting the accused set the threshold for review is not a cost saving. |

## What was known at the time

Six consecutive components had moved from the model side to the arithmetic side:
`CalibratorAgent` in Phase 7 (ADR 0025), then `distribution`, `BiasDetective`,
`ScoringAgent`, `FusionBridge` (ADR 0026) and `CollateralAgent` (ADR 0027). ADR
0027 stopped calling that a run of good corrections and read it as evidence
about `ARCHITECTURE.md`: the judgement is real and is being pushed steadily
earlier, into extraction, paid for once and written down as an edge.

That same ADR made a prediction, in writing, about where the run would stop:

> That also predicts where it stops: `ChallengerAgent` and `ReviewTriageAgent`,
> whose input is prose nobody has reduced to a record, should keep their routes.

`EST-0010` priced this phase on that prediction holding, and it holds. The
input to a challenge is a `prosecution` string. Nothing upstream reduced it to
a record, because it *is* the record — the prose is the allegation.

What was **not** known: whether the concede rate this produces is meaningful.
`MockProvider` synthesises a bare boolean true seventy per cent of the time
(`praxis.llm.synthesis._TRUE_BIAS`), so no offline run can answer the question
the metric exists for. That is recorded as a limitation rather than engineered
around — see the assumptions below and `docs/reports/phase-9.md`.

## Assumptions

| # | Assumption | Predicate | Expiry condition |
| - | ---------- | --------- | ---------------- |
| 1 | The concede rate against a real model sits inside the band that distinguishes a challenger from a rubber stamp or a silencer | `concede_rate >= 0.05` | `on_event("the first live challenging run reports a concede rate")` |
| 2 | And below its upper bound, for the same reason in the other direction | `concede_rate <= 0.6` | `on_event("the first live challenging run reports a concede rate")` |
| 3 | The confidence floor refuses a real share of verdicts rather than none, so it is a threshold and not decoration | `undecided_challenges >= 1` | `on_event("a live run records no undecided challenge across at least 20 findings")` |
| 4 | A challenge costs one call per batch and not one per finding | `challenge_calls <= challenged_findings` | `on_event("a run reports more calls than findings challenged")` |

Assumptions 1 and 2 are stated as a pair on purpose. A single bound would be
satisfied by an agent that failed in the other direction, which is the same
control discipline every property test in `tests/agents/` now carries.

## Consequences

**Accepted costs.** Every finding a person sees now costs a `reason`-tier call
before they see it, and that call happens after the finding has already been
computed — so the pipeline pays for judgement about work it has already done.
That is the intended trade and it is bounded by batching, but it is the first
cost in this project that scales with *findings* rather than with documents.

Offline, the concede rate is not evidence about the agent. Every report carrying
it has to say so, and the temptation to reshape the response schema until the
mock produces a comfortable number has to be refused explicitly — which is why
`Judgement.upheld` mirrors `Verdict`'s own polarity rather than being chosen for
how it reads.

**Reversal cost.** One line in `praxis/config/models.py` moves the name into
`NON_LLM_AGENTS`, plus whatever deterministic rule replaces the call and the
tests that rule needs. The prompt and its version stay in the library either
way, because traces produced under it must remain reproducible (ADR 0014). The
expensive half of a reversal is not the code; it is that every concede rate
measured before the change stops being comparable with every one after it.
